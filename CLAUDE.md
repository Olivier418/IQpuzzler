# Codebase map

Import layering (no cycles): `constants` <- `classes` <- `serialization` <- `solving` <- `benchmark` <- `plotting`. `classes` never imports `serialization`; anything needing both lives in `solving.py`/`serialization/`.

Core model (`classes/`, layered bottom-up):
- `lattice.py` — `Lattice`: geometry of a board/block's axes (orthogonal vs. offset, e.g. triangular/pyramid). Derives gram2 / unit_vectors. Leaf, no deps.
- `blocks.py` — `Block` (shape + color/letter + its own Lattice), `BlockCollection` (UserDict, int idx -> Block, unique letters).
- `boards.py` — `Board` (cells: bool ndarray + Lattice), `RegularBoard`, `PyramidBoard(width, depth)` subclasses.
- `setup.py` — `Setup`: board + blocks + **all valid placements** (expensive, computed once, shared by reference across every Puzzle/Book built on it). `placement_cells[block_idx]` = compact cell-index array per valid orientation/position. Compact indexing: grids only cover the board's real cells; `to_full_grid(grid)` / `to_compact_grid(full)` convert to/from the full board-shaped array (used at the rendering / disk boundaries). `render(grid, header=None, leftover_idcs=None)` is a thin facade delegating to `rendering.py`.
- `state.py` — `State`: mutable solve state (grid + chosen_placement_idx, `name` = None) over a shared `Setup`. `place`/`remove` (checked) vs `place_unchecked`/`remove_unchecked` (used by Solver). `.solve(seed, time_limit, max_solutions, **options)` is a plain generator delegating to `Solver`; a named state's solutions are renamed "<name> (solution i)"; it prints nothing (progress printing is `solving.py`'s job). `render(show_leftover=True)` (via `_print_header`, overridable) builds header + grid + shape diagrams of any still-unplaced blocks; `__repr__` calls it. `Puzzle(State)`: named, has difficulty, optionally pre-filled from a letter grid (`_initialize_grid`, transposes JSON (depth,width) -> internal (width,depth)); header `"Puzzle {name}"`.
- `puzzlebook.py` — `PuzzleBook(UserDict)`: named collection of Puzzles sharing one Setup. `__repr__` expands every Puzzle with `show_leftover=False`.
- `game.py` — `Game`: top-level container of `books` (name->PuzzleBook), `puzzles` (standalone), `setups` (board_key->Setup). One Game per `games/<GameName>/` folder.
- `source.py` — `Source` (frozen dataclass): game/book/puzzle name triple recording where a Puzzle/Book was loaded from. `relative_dir()` -> `<game>/books/<book>` (book), `<game>/puzzles/<puzzle>` (standalone), `<game>/books/<book>/<puzzle>` (one puzzle out of a book). Set by `serialization.loading.load_game`, `None` for hand-built objects.
- `solutions.py` — pure data containers, no solving or I/O: `PuzzleInfo` (difficulty, nr_empty_spaces — the source Puzzle's, never stored on `Solution`), `SolveStats` (puzzle_name, options, seed, duration, elapsed; `options` = free-form solver kwargs besides the seed, currently always empty, kept to tell solver variants apart in benchmarks), `Solution` (puzzle_name + full board-shaped `grids` + game/book_name (transient, recovered from the save folder on load) + optional live `puzzle`; `to_states(setup)` and `puzzle_info(puzzles)` only use the live puzzle/setup given — for a Solution loaded from disk use `serialization.solution_states` / `solution_puzzle_info`; `__repr__` renders when a live puzzle exists, else a one-line summary), `SolutionBook` and `SolveStatsBook` (UserDicts keyed by puzzle_name with book-level game/book_name (+ options/seed for stats); `.name` computed via `_book_name`).
- `solver.py` — `Solver`, out of scope for structural review. Exhaustive exact cover with one strategy (cell-MRV), no flags: `Solver(state).solve(seed=None, time_limit=inf, max_solutions=inf)` yields every solution as a `state.copy()`, stopping early once either limit is hit (time checked once per node; a sticky `stopped` flag unwinds the recursion so the Solver stays reusable). Each node branches on the open cell covered by the fewest live placements and tries every placement covering it; candidates ordered lexicographically by their cells' sorted live-placement counts (only changes when solutions arrive, never which). **Flat state**: `_build_flat_tables` lays every block's placements end to end (`_placement_cells_flat`, rows padded with the dummy cell `n_cells`; block position `p` owns global ids `_block_start[p]:_block_start[p+1]`, `_block_of`, `_cell_lists[c]`, lazily cached `_overlapping(gid)`). A node is `(live, block_count, cell_count)`; `_root_node` builds the first, `_place` derives each child. **Seeds**: never reorder `Setup.placements`; a seed draws random tie-break priorities per placement/cell once per solve (identity when unseeded). `SYMMETRY_NOTES.md` has the findings for adding symmetry back (the old symmetry code is deleted; see there for where it lives in git history).
- `rendering.py` — terminal display: `grid_lines`, `block_shape_lines`, `legend_lines`, `render(board, blocks, grid, header=None, leftover_idcs=None)`. Plain `Board`/`BlockCollection`/grid args, no `Setup` dependency.
- `_utils.py` — `_assert_unique`, `_shared` (dedup/consistency helpers).
- `__init__.py` — the public re-export surface; import from here, not submodules, in new code.

Serialization (`serialization/`; imports `classes`):
- `loading.py`: `load_blocks`/`load_boards`, `load_game(dir)` (auto-discovers `books/*.json` + `puzzles/*.json`, builds a full `Game`). Names are never read from a JSON `"name"` field except for puzzles inside a book file: `Game.name` = folder name, `PuzzleBook.name`/standalone `Puzzle.name` = file stem. A board's optional `"cells"` is row strings (`"X"` = cell). Book-file parsing is shared via `_read_book_file`/`_read_puzzle_file`. Cold-start helpers for Solutions loaded from disk: `load_setup_for_puzzle`, `load_puzzle_info_for_puzzle` (reads JSON only, no Setup), and their Solution-level entry points `solution_states(solution)` / `solution_puzzle_info(solution, puzzles=None)` (live puzzle / `puzzles` first, else the game files).
- `jsonio.py`: leaf letter-grid helpers. A grid is one string per row (`"BBB        "`), a pyramid a list of such layers; `" "` = empty/off-board. `parse_letter_grid`, `letter_grid_to_rows` (from internal (width, depth[, height])), `dump_json(obj, path)` (indent 2, list of strings one row per line).
- `paths.py`: leaf; where runs live and how to read names back from a path: `next_free_idx_dir(base, prefix="result")` (`result_1`, `result_2`, ...; `benchmark` prefix for benchmarks), `next_run_dir(source, root)`, `game_book_from_run_dir`, `puzzle_name_from_run_dir`, `single_entry`.
- `solutions_io.py`: `write_solutions`, `load_solutionbook`. solutions.json stores grids as letter rows (block letter from the live puzzle's blocks, else the game's `blocks.json`; non-block -> `" "`). Top level is a bare list: `flat=True` (one puzzle; name recovered from `.../<puzzle_name>/<idx>/`) writes just the grids, `flat=False` (whole book, or benchmark trial folders) writes `{"puzzle_name", "grids"}` objects; `load_solutionbook` tells them apart by the first element.
- `stats_io.py`: `write_solve_stats`, `load_solve_stats_book`. stats.json keeps an object wrapper (`options`, `seed`, then per-puzzle data); `_read_options` folds the legacy top-level solver flags into `options` so old runs still load.
- `runs.py`: `save_solution_run(solution_book, stats_book, folder, flat=True)` / `load_solution_run(folder)` — the solutions + stats pair in one folder.
- game/book/puzzle names are never written into JSON; they follow from the folder. On-disk layout: `games/<Game>/{blocks.json, boards.json, books/*.json, puzzles/*.json}`; solutions mirror it under `solutions/<Game>/<books|puzzles>/<name>/[<puzzle_name>/]result_<idx>/{solutions.json, stats.json}`; benchmarks under `benchmarks/<Game>/<books|puzzles>/<name>/[<puzzle_name>/]benchmark_<idx>/<config-label>/test{seed}/{solutions.json, stats.json}`. `solutions/` and `benchmarks/` are git-ignored.

Running (`solving.py`, `benchmark.py` at the repo root):
- `solving.py`: `solve_puzzle(puzzle, seed, verbose, save, path, solutions_root, time_limit, max_solutions, **options) -> (Solution, SolveStats)` and `solve_puzzlebook(book, ...) -> (SolutionBook, SolveStatsBook)` (one combined `flat=False` save). Solves, times, packages (`make_result`, `single_run_books`) and auto-saves under `solutions/` mirroring the `Source`. `time_limit`/`max_solutions` are deliberately not part of `options` (never recorded or treated as a benchmark config). `verbose` is a `Verbosity` IntEnum (cumulative): `SILENT` 0; `SUMMARY` 1 "Found 21 solutions to puzzle x in 1.23s"; `EACH_SOLUTION` 2 also "Found 3rd solution to puzzle x in 0.42s" per solution; `SHOW_SOLUTIONS` 3 prints each solved puzzle instead of that line (its header already names puzzle + solution number). The summary line ends every level >= 1 (at level 3 it omits "to puzzle x" when a puzzle was rendered above it).
- `benchmark.py`: `run_benchmark`/`load_benchmark`, `config_key`/`config_label` (a config = dict of solver keyword options; `DEFAULT_CONFIGS = [{}]`). Trials run in a subprocess with a wall-clock cap `T`: the parent owns the authoritative deadline and kills the worker, which also gets `time_limit=T`. Takes a `Puzzle`; builds one-entry books per trial via `solving.make_result`/`single_run_books`.

Plotting (`plotting/`): `plot_difficultyspace.py` and `plot_solve_timeline.py` (also takes a `SolveStatsBook` for timing) read difficulty/nr_empty_spaces via `serialization.solution_puzzle_info(sol, puzzles)`. `plot_benchmark.py`: `plot_benchmark(stats_books, show_trendline=True, T=None)` draws each trial's cumulative-solutions step curve (anchored at (0,0)) plus the per-config average on a 500-point grid, colored from `constants.CONFIG_PALETTE`; `T` pins the x-axis to the budgeted window. Trendline rate = `_poisson_rate`, the homogeneous-Poisson MLE (total solutions / total observed time, pooled over trials).

`main.py` is a scratch file of mostly commented-out usage examples, not a real entrypoint. `main.ipynb` is a demo notebook.

`constants.py`: grid sentinels (EMPTY/OUTSIDE_BOARD/UNPLACED), `SOLUTION_DIR`/`BENCHMARK_DIR`/`GAMES_DIR` (Paths), color tables used only in plotting.

Testing (`tests/`, stdlib `unittest`; run the whole suite by running `run_tests.py` in the repo root, ~30 s; nothing is read from or written to `solutions/`/`benchmarks/`): `tests/data/<Game>/<book>.json` -- hand-checked solutions used as a fixture (`{puzzle name: [solution, ...]}`, a solution being a list of layers (1 on main/alt boards, 5 on a pyramid) of row strings, `" "` = off-board). IQpuzzler holds one sampled puzzle per difficulty per book; IQpuzzlerPRO holds every puzzle, verified against the solution booklet. Loaded by `_helpers.load_known_solutions`. `test_solver.py` -- known solutions must be valid and among the solver's; every PRO puzzle's booklet solution must be found and every PRO puzzle must have exactly one solution (`pyramid_puzzles/120` intentionally FAILS: the real game's claim doesn't hold there, 5 solutions); an unsolvable hand-built puzzle has no solution; seeds give identical solution sets; the first 25 solutions of the empty boards are valid and distinct; time/count limits. `test_data.py` -- puzzle-file sanity (blocks-fill-board is enforced by `Setup._validate` at load time, not tested separately). No tests for terminal output formatting. `test_serialization.py` -- letter-grid helpers and a save/load round trip of solutions.json (temp folder only). `_helpers.assert_valid_solution` is the shared validity check.
